# TaskFlow — навчальний JavaScript To‑Do застосунок

Адаптивний менеджер завдань на **HTML5, Bootstrap 5.3, CSS та чистому JavaScript**.

**Онлайн:** https://parashchuk23-oss.github.io/html-homework/javascript-task-4-taskflow/

## Файли
- [index.html](index.html) — форма, лічильники та список.
- [style.css](style.css) — адаптивні стилі.
- [script.js](script.js) — масив стану, обробники подій і `renderTasks()`.

## Функціональність
- Додавання завдання назвою від 3 символів (пробіли по краях ігноруються).
- Позначення виконаного завдання через чекбокс, повторне натискання повертає його в активні.
- Видалення завдання.
- Лічильники активних і виконаних завдань.
- Порожній стан, коли жодного завдання немає.
- Підтримка мобільної ширини через Bootstrap і власний CSS.

**LocalStorage увімкнено:** завдання залишаються після оновлення сторінки у тому самому браузері. Фільтрів, React, сервера чи бази даних немає.

## Що таке state?

`tasks` — **стан (state)** застосунку: поточні дані, з якими працює інтерфейс.

```js
let tasks = [
  { id: 1, text: "Повторити JavaScript", completed: false }
];
```

- `id` — унікальний номер завдання;
- `text` — його назва;
- `completed` — виконане (`true`) чи активне (`false`).

Масив `tasks` — **джерело правди**: DOM лише відображає його вміст. У прикладі реального коду масив спочатку порожній: `let tasks = []`, але під час запуску він відновлюється через `loadTasks()` з LocalStorage.

## Як працює renderTasks()?

`renderTasks()` заново відображає весь поточний список:
1. `taskList.textContent = ""` очищає попередні елементи.
2. `tasks.forEach(...)` проходить по кожному завданню.
3. `document.createElement(...)` створює пункт списку, чекбокс, текст і кнопку.
4. `append(...)` вставляє ці елементи на сторінку.
5. `tasks.filter(...)` підраховує активні та виконані завдання.
6. `textContent` оновлює лічильники.
7. `classList.toggle("d-none", ...)` показує або ховає повідомлення «Поки немає завдань».

### Коли викликається renderTasks()?

| Подія | Зміна state | Результат |
|---|---|---|
| Додавання через `submit` | `tasks.push({id, text, completed:false})` | З'являється нове завдання; активні +1 |
| Зміна чекбокса (`change`) | `task.completed = checkbox.checked` | Завдання перекреслюється; лічильники перераховуються |
| Натискання «Видалити» (`click`) | `tasks = tasks.filter(task => task.id !== id)` | Завдання зникає |
| Перший запуск | `tasks = loadTasks()` | Відновлюється список або показується порожній стан |

Ключова схема: **дія → зміна масиву tasks → saveTasks() → renderTasks() → новий інтерфейс**.

## Що потрібно пояснити викладачу
- `addEventListener` відстежує `submit`, `input`, `click` і `change`.
- `createElement` створює HTML-елементи програмно.
- `textContent` записує текст і очищає список.
- `append` вставляє елементи в DOM.
- `forEach` перебирає всі завдання для відображення.
- `filter` використовується для видалення та підрахунку статусів.
- `renderTasks()` синхронізує видиму сторінку зі станом.

## Оновлення: збереження у LocalStorage

Для збереження використано ключ **`taskflow-tasks`**. Зберігаються тільки дані кожного завдання: `id`, `text` і `completed`; HTML не зберігається.

### 1. Запис у сховище

```js
function saveTasks() {
  try {
    localStorage.setItem("taskflow-tasks", JSON.stringify(tasks));
  } catch (error) {
    console.warn("Не вдалося зберегти завдання в LocalStorage:", error);
  }
}
```

`JSON.stringify(tasks)` перетворює масив об'єктів на рядок JSON. `localStorage.setItem()` зберігає цей рядок під ключем. Функція викликається після **додавання**, **видалення** та **зміни completed**.

### 2. Відновлення під час завантаження

`loadTasks()` отримує рядок через `localStorage.getItem(STORAGE_KEY)`, перетворює його назад на масив за допомогою `JSON.parse()` та перевіряє структуру даних. Якщо запису немає, JSON пошкоджений, дані не є масивом або містять некоректні об'єкти, повертається порожній масив `[]`. Обробник `try/catch` також захищає від помилок доступу до сховища.

Після цього обчислюється `nextTaskId` як **найбільший збережений id + 1**, а `renderTasks()` відображає список. Це не дає новим завданням отримати вже використаний id після перезавантаження.

### 3. Перевірка

1. Додайте два завдання та позначте одне виконаним.
2. Оновіть сторінку: обидва завдання, статус і лічильники мають залишитися.
3. Видаліть завдання й оновіть сторінку: видалене не повинно повернутися.
4. В DevTools → Application → Local Storage знайдіть ключ `taskflow-tasks`.
5. Якщо запис відсутній або JSON некоректний, застосунок має показати порожній список без зупинки JavaScript.

**Важливо:** LocalStorage прив'язаний до **origin** (схема, домен, порт). Інший сайт не отримує ці дані автоматично. У LocalStorage не можна зберігати паролі, токени та інші секрети. Дані зберігаються локально у браузері, не синхронізуються між пристроями та можуть бути видалені під час очищення даних сайту. Якщо сховище заблоковано або заповнено, застосунок продовжить працювати в пам'яті сторінки, але зміни можуть не зберегтися.
